# Weave In：讓每個人的想法都能進入共同討論

Weave In 是一個從多人會議協作出發的 agent-native meeting app。我們關注 groupthink帶來的問題：當某個人提出方案，其他人可能在沒有充分討論的情況下附和，讓不同的看法與疑慮沒有被提出。多人會議也常有另一種困難：討論十分熱烈，有人雖然有想法，卻一直找不到介入的時機，等到能夠發言時，想法已經遺忘，或話題早已改變。

Weave In 支持參與者在協作中保持 critical thinking：保留自己的判斷、提出疑問，並一起檢視方案的假設與依據。它讓這些有價值的想法先被保留、釐清，再進入共同討論。因此，Weave In 選擇以 meeting app 為形式，在會議正在進行、想法還來得及影響決策的時候提供協助。

它的完整體驗採取 agent-native 的設計。相較於在 meeting app 裡放入一個 chatbot，我們把出發點反過來：讓 meeting app 運作在 agent 能夠操作的瀏覽器中。使用者可以帶著自己熟悉的 agent 進入會議，讓它理解討論脈絡、執行任務，並把成果帶回共享空間。Weave In 仍可在一般瀏覽器中使用，並在 Codex 內建瀏覽器中透過工具整合，提供完整的協作體驗。

在這個設計裡，三種 agent 分別服務不同的需求。

第一種是團隊 agent：Omni。它關注團隊共同的討論目標，協助提醒尚未處理的問題，以及相對於 agenda 的話題偏移。例如，當大家準備通過一項方案，卻還沒有回應前面提出的疑慮時，Omni 可以把問題重新帶回討論；當話題逐漸偏離原定目標時，它則提醒大家確認要回到原題，還是調整議程。它協助團隊保持對問題的注意，決定仍由參與者做出。

第二種是個人的即時對話 agent：Muse。它使用 GPT-Live-1，讓使用者在會議中透過即時語音進行私人 side chat。當一個想法還不確定、對別人的說法有疑問，或看不懂螢幕分享上的公式與圖表時，使用者可以先與 Muse 討論，補足理解、整理思緒，再決定如何帶回會議。私人討論留在個人空間，由使用者選擇要分享的內容。

第三種是使用者原本就習慣使用的個人 agent，例如 Codex。它負責可以在背景進行的非同步任務，包含查閱資料、比較方案、檢查程式實作，以及整理結構圖。這些工作可以和會議同時推進，讓參與者在持續討論的過程中，取得進一步的分析與查證結果。

為了把 Codex 的工作接上會議，我們透過 WebMCP 提供會議狀態與操作工具。Codex 能在授權範圍內讀取各參與者的即時逐字稿、公共聊天、螢幕分享畫面，以及白板內容，並依照使用者的指示，把完成的成果發布到公共 chat 或放上共享白板。這讓 agent 能根據現場脈絡工作，也讓所有參與者能接著使用它的成果。

會議中的想法也需要一個讓人與 agent 共同檢視、討論和修改的地方。共享白板把流程、架構與關係留在同一個畫面上，讓參與者能指認問題、補充內容，或直接畫出自己的想法。我們特別將白板整合在自己可控制的 meeting app 環境中，讓 agent 能透過 WebMCP 提供的 structured tools，直接讀取節點、文字與連線等結構化 context，並針對既有元素新增、修改或連接。這讓 agent 有清楚的介面取得目前狀態、精確操作共同成果，也能接續人剛完成的修改。

為了讓 agent 更方便地建圖，Codex 可以使用 Mermaid 描述流程或架構，再由 Weave In 將受支援的圖形轉換成白板上的可編輯節點、文字與連線。Agent 使用熟悉的文字形式建圖，人則能以所見即所得的方式移動節點、修改標籤與調整箭頭；修改後的結構仍能由 agent 讀取與操作，讓雙方在同一份成果上持續協作。

例如，團隊正在討論一項新功能，一位成員對實作方式有疑慮，卻一時插不上話。他先與 Muse 釐清問題，再請 Codex 查閱相關程式。Codex 完成後，依照他的指示把分析與流程圖分享到會議中，大家直接在白板上調整方案；如果討論逐漸偏離原定目標，Omni 則提醒團隊確認議程。原本可能沒有被說出口的想法，就有機會成為共同討論的一部分。

實作上，我們以多人會議、即時逐字稿與共享白板為基礎，整合了 Muse 的即時對話、WebMCP 的狀態讀取與操作工具，以及團隊提醒與非同步成果分享流程。Codex 同時也是開發工具，協助實作功能、檢查工具介面，並驗證從讀取會議到交付可編輯成果的完整體驗。

Weave In 讓即時發言、私人思考與非同步工作彼此銜接，讓每個人都能以適合自己的方式，為共同討論做出貢獻。
